# ADR: фундамент профессиональной beta

Дата: 08.10.2026. Статус: принят для первого вертикального этапа.

## Решения

1. SQLite остаётся production-хранилищем при одной реплике Bothost. Схема v6 добавляет
   `user_settings` и `calculation_profiles`; миграция идемпотентна и сохраняет старые
   расчёты/черновики.
2. Профиль хранит только повторно используемые допущения (`indoor`, воздухообмен, запас),
   но не адрес и геометрию объекта.
3. Локализация использует строгие ключи и parity-проверку RU/UZ. Это фундамент; перенос
   всех строк существующего wizard выполняется вместе с его разбиением на feature routers.
4. Telegram получает короткий клиентский итог. Полный инженерный протокол остаётся в PDF
   и сохранённом отчёте.
5. Неподтверждённые климатические значения не добавляются. Отсутствующая строка таблицы 4
   безопаснее ручного ввода, чем ложная маркировка значения как нормативного.

## Миграция и откат

Перед деплоем остановить единственную реплику и сделать SQLite `.backup`. Код v6 можно
откатить на предыдущий образ: новые таблицы предыдущей версии не мешают чтению таблиц
`calculations`/`calculation_drafts`. Для полного отката данных восстановить backup только
при остановленном боте; не копировать один `.db` во время записи WAL.
