# ADR: production-фундамент U-Calc

Дата первоначального решения: 08.10.2026. Актуализировано: 12.10.2026.
Статус: принято для U-Calc 0.3.x.

## Решения

1. SQLite schema v8 является production-хранилищем при одной активной реплике Bothost.
   Межпроцессный lock захватывается до миграций и запуска polling. Схема хранит расчёты,
   черновики, настройки, профили, неизменяемые PDF версий и минимальный приватный аудит.
2. Профиль хранит только повторно используемые допущения (`indoor`, воздухообмен, запас),
   но не адрес, название или геометрию конкретного объекта.
3. RU и UZ Latin используют один строгий каталог с автоматической parity-проверкой.
   Основной мастер, вложенные редакторы, история, ошибки, инженерный отчёт и PDF
   локализованы; экспертный текстовый импорт остаётся дополнительным ускоренным путём.
4. Telegram показывает компактный проверяемый итог, а полный инженерный протокол
   сохраняется вместе с расчётом. PDF версии записывается один раз и впоследствии
   скачивается без незаметной перегенерации другим расчётным движком.
5. Неподтверждённые нормативные климатические значения не добавляются в каталог.
   Параметр Б встроенных городов хранится только с точной строкой и колонкой официального
   PDF. Пользовательский override и полный ручной климатический профиль получают статус
   `user_supplied_unverified` и сохраняют provenance каждого значения.
6. Доменная фабрика считается границей доверия для Telegram FSM: она повторно проверяет
   диапазоны, типы, геометрические балансы и структуру коллекций, включая восстановленные
   черновики, которые могли быть созданы предыдущей версией приложения.

## Миграция и откат

Перед deploy нужно создать SQLite backup штатной командой `u-calc-backup`; она использует
online-backup API и проверяет целостность результата. Миграции v1→v8 идемпотентны и не
переписывают существующие расчёты или черновики; новые таблицы и nullable-поля не мешают
чтению старых записей.

Откат к предыдущему образу допустим только после проверки, что он понимает текущую
схему. Для полного отката данных используется `u-calc-restore --yes` при остановленном
боте: команда проверяет polling-lock и целостность, создаёт аварийную копию текущей БД,
очищает старые WAL/SHM и атомарно заменяет базу. Нельзя копировать отдельный `.db` во
время записи WAL и нельзя запускать две реплики на одном volume.

## Эксплуатационные границы

- одна активная реплика и один постоянный volume;
- backup и retention внешних логов остаются ответственностью владельца Bothost-проекта;
- Telegram polling с настоящим токеном проверяется только в целевом окружении;
- расчёт является инженерным предварительным подбором, а не заменой проекту и проверке
  исходных данных профильным специалистом.
