# U-Calc — Telegram-бот расчёта теплопотерь

U-Calc помогает мастеру отопления оценить пиковую тепловую нагрузку квартиры или
частного дома. Бот показывает не только итоговые кВт, но и исходные данные, `R`, `U`,
`ΔT`, потери каждой конструкции, воздухообмен, мостики холода и отдельный
эксплуатационный запас.

Это прозрачный предварительный инженерный расчёт, а не автоматически готовая проектная
документация. ГВС и месячное потребление энергии в результат не входят.

## Возможности beta

- быстрый и расширенный сценарии расчёта;
- квартира (средний, первый, последний этаж) или частный дом;
- стены общей площадью, по размерам, периметру или отдельными группами через
  пошаговый редактор; текстовый импорт оставлен как экспертный режим;
- до 10 последовательных слоёв в каждой пошагово собранной конструкции стены;
- структурированная ориентация каждой стены с нормативной добавкой β и наследованием
  привязанными окнами и дверями;
- материалы и утеплители из версионируемого каталога либо паспортная `λ`;
- группы окон и дверей с количеством, размерами, паспортным `U` и привязкой к стене;
- пошаговый редактор групп окон и дверей с немедленной проверкой площади выбранной стены;
- пол/потолок к улице, грунту, холодной зоне или отапливаемому соседу;
- фактическая температура соседней зоны и реальная конструкция перекрытия;
- зональный пол по грунту по приложению 9 ШНҚ 2.04.05-22;
- расчётный климат Ташкента, Самарканда, Нукуса или профиль пользователя;
- средний, расчётный, экстремальный и сценарий климатического риска;
- воздухообмен и КПД рекуперации;
- процентная оценка мостиков холода либо пошаговый точный ввод `ψ × L`;
- история каждого Telegram-пользователя и её удаление;
- главное меню и кнопочный CRUD профилей расчёта;
- автоматическое применение default-профиля к температуре, воздухообмену и запасу;
- кнопочное редактирование этих параметров профиля с версионированием;
- устойчивые черновики, повторный показ шага после `/resume`/`/back` и защита от
  параллельных действий одного пользователя;
- настройка языка RU/UZ Latin с проверкой равенства ключей локализации;
- настраиваемое имя мастера или организации в PDF-отчёте;
- необязательный allowlist Telegram ID.

## Расчётная модель

Для непрозрачной конструкции:

```text
R = Rsi + Σ(d / λ) + Rse
U = 1 / R
Q = U × A × ΔT
```

Направление теплового потока хранится явно (`стена`, `пол`, `потолок`, `кровля`).
Поверхностные сопротивления выбраны по ISO 6946:2017: `Rsi=0,13` для стены,
`0,17` для потока вниз, `0,10` для потока вверх; для наружной поверхности
`Rse=0,04 м²·К/Вт`.

Воздушные потери:

```text
Qmech = 0,33 × Lmech × ΔT × (1 − η)
Qnatural = 0,33 × Lnatural × ΔT
Qinfiltration = 0,33 × Linfiltration × ΔT
```

Здесь `L` — расход воздуха в м³/ч, `η` — КПД рекуперации. Рекуперация не
уменьшает естественную вентиляцию или инфильтрацию. Быстрый режим с общей кратностью
явно считается невосстанавливаемой оценкой.
Если температура холодного подвала/чердака неизвестна, используется явно отмеченная
оценка 70% наружной `ΔT`; для упрощённого пола по грунту — 50%. Эти коэффициенты не
выдаются за нормативные.

В рекомендуемом зональном методе пола по грунту используются полосы шириной 2 м и
`R=2,1 / 4,3 / 8,5 / 14,2 м²·К/Вт`. Угловые участки первой зоны относятся к двум
примыкающим наружным стенам и считаются дважды. Для утепляющего слоя с
`λ < 1,2 Вт/(м·К)` добавляется `d/λ`.

## Архитектура

```text
src/u_calc/
├── bot.py                  # компактный совместимый facade/console entry point
├── app.py                  # сборка приложения, middleware и polling
├── handlers/survey.py      # Telegram-сценарий опроса
├── handlers/menu.py        # главное меню, язык и профили расчёта
├── handlers/history.py     # история, отчёты, сравнение и удаление расчётов
├── handlers/opening_editor.py # пошаговые группы окон/дверей и привязка к стене
├── handlers/bridge_editor.py # точные мостики холода ψ × L
├── handlers/wall_editor.py  # разные стены и до 10 слоёв конструкции
├── i18n.py                 # строгий RU/UZ-каталог переводов
├── states.py               # FSM-состояния
├── keyboards.py            # inline-клавиатуры
├── middleware.py           # доступ, rate limit, навигация, черновики и блокировки FSM
├── config.py               # Settings из окружения
├── models.py               # доменная модель и валидация
├── calculator.py           # чистые инженерные формулы
├── catalog.py              # материалы, окна, двери, климат и версии
├── parsing.py              # строгий разбор пользовательского ввода
├── report.py               # объяснимый текстовый отчёт
├── pdf_report.py           # профессиональный PDF
├── storage.py              # SQLite, WAL, черновики, версии и миграции
└── services/
    ├── building_factory.py # единая сборка модели из FSM-ответов
    └── calculation_service.py
```

Расчётное ядро не зависит от aiogram и тестируется отдельно. Telegram-слой не дублирует
инженерные правила.

## Локальный запуск

Нужен Python 3.11+ и токен от [@BotFather](https://t.me/BotFather).

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
cp .env.example .env
export BOT_TOKEN='ваш-токен'
u-calc-bot
```

Переменные окружения:

| Переменная | Обязательна | Значение |
|---|---:|---|
| `BOT_TOKEN` | да | токен Telegram; никогда не логируется |
| `DATABASE_PATH` | нет | SQLite, по умолчанию `data/u_calc.db` |
| `LOG_LEVEL` | нет | `DEBUG/INFO/WARNING/ERROR/CRITICAL` |
| `APP_TIMEZONE` | нет | часовой пояс истории, по умолчанию `Asia/Tashkent` |
| `ALLOWED_USER_IDS` | нет | Telegram ID через запятую; пусто — доступ всем |
| `RATE_LIMIT_PER_MINUTE` | нет | максимум действий пользователя в минуту, 30 |
| `CALCULATION_RATE_LIMIT_PER_MINUTE` | нет | максимум тяжёлых расчётов/PDF в минуту, 6 |
| `MAX_MESSAGE_LENGTH` | нет | предел входного текста, максимум Telegram 4096 |
| `HISTORY_RETENTION_DAYS` | нет | хранение завершённых расчётов, 730 дней |
| `DRAFT_TTL_DAYS` | нет | хранение незавершённого черновика, 30 дней |

Проверки:

```bash
ruff check src tests scripts main.py
pytest -q
python -m compileall -q src tests scripts main.py
python scripts/sync_requirements.py
```

`requirements.txt` генерируется из runtime-зависимостей `pyproject.toml`; после изменения
зависимостей его нужно синхронизировать указанным скриптом.

## Docker и Bothost

Образ запускается без открытого порта: Telegram-бот использует long polling. Процесс
работает от непривилегированного пользователя, а entrypoint подготавливает права
смонтированного каталога данных.

```bash
export BOT_TOKEN='ваш-токен'
docker compose up --build -d
docker compose logs -f bot
```

Для Bothost выберите сборку из собственного `Dockerfile`, задайте переменные окружения
из таблицы и подключите постоянное хранилище к `/app/data`. Порт публиковать не требуется.
`main.py` является только запасным входом после установки src-layout пакета и не
предназначен для запуска из необработанного checkout без установки зависимостей.
Полная инструкция: [`docs/BOTHOST_DEPLOY.md`](docs/BOTHOST_DEPLOY.md).

База использует WAL и `busy_timeout`; каталог `/app/data` должен быть постоянным.
Перед обновлением можно сделать резервную копию SQLite штатной командой:

```bash
sqlite3 /path/to/u_calc.db ".backup '/path/to/u_calc-backup.db'"
```

Восстановление выполняется только при остановленном экземпляре бота заменой файла БД
проверенной резервной копией. Не копируйте один лишь `.db`, пока процесс пишет в WAL.

## Источники и ограничения

- пол по грунту: приложение 9
  [ШНҚ 2.04.05-22](https://lex.uz/uz/docs/-7262276?ONDATE=11.09.2024&action=compare);
- климат: [ШНҚ 2.01.01-22](https://lex.uz/uz/acts/-6363141);
- сопротивления поверхностей: ISO 6946:2017;
- `λ` материалов и `U` типовых окон/дверей — справочные проектные значения.

Для рабочего проекта инженер должен проверить адресный климат, влажностные условия,
паспортные `λ/U`, инфильтрацию, ориентацию и ветер, узлы мостиков холода и местные нормы.
«Климатический риск» — консервативный резерв, а не прогноз погоды на конкретную дату.

Подробная продуктовая спецификация находится в
[`docs/PRODUCT_SPEC.md`](docs/PRODUCT_SPEC.md).
